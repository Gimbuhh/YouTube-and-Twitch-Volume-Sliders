# Testing

`npm run check` runs deterministic builds, metadata/syntax validation, Node unit and jsdom integration tests, generated-artifact checks, and the Chrome and Firefox browser suites. `npm test` also builds and runs Node plus both browser suites. Missing prerequisites fail these commands; browser checks never silently skip.

Install Google Chrome and FFmpeg, run `npm ci`, then `npm run browsers:install` once to download the isolated Firefox test build. Linux may require `node node_modules/playwright-core/cli.js install --with-deps firefox`. Test runs themselves use local fixtures without downloading browsers or contacting YouTube/Twitch. CI runs the core checks and Chrome suites on Windows, plus Firefox on Linux with a PulseAudio null sink so real audio processing needs no physical output device. Both jobs are required for complete verification; release verification also runs both browser suites with a virtual audio output.

For a quicker development pass, `npm run check:core` retains the browser-independent integrity/Node checks. `npm run test:node` runs Node tests alone. These are focused checks, not substitutes for full verification. `npm run test:browsers`, `npm run test:chrome`, and `npm run test:firefox` provide focused browser runs without repeating Node tests.

Unit tests cover shared settings, storage failure and recovery, volume functions, custom adjustment steps, smooth wheel accumulation, zoom-gesture pass-through, and major-tick press behavior. Integration tests execute the generated `dist/*.user.js` files in explicit YouTube and Twitch fixtures. They verify standalone startup, mute-safe restoration, slider and wheel step selection, fixed keyboard steps, adaptive ticks, direct slider intent, accessible controls, options-dialog focus, tab keyboard navigation and preview cleanup on tab switches, options and resets with blocked storage, mode off, external detachment, and reattachment. This prevents source-only scaffolding from passing while production artifacts are broken.

Tests do not contact either service. A frozen install may access a package registry; optional reference audio for the comparison is acquired separately.

Release preflight tests exercise real temporary archives, checking both platform hashes, historical backfills, package-version mismatches, missing files, and directory substitutions. The runtime helper also verifies that restarted mutation observers cannot deliver callbacks after teardown.

Options lifecycle regressions verify that popup replacement does not accumulate page-level release listeners and that previews end on release, cancellation, tab switches, close, and replacement. Browser checks also exercise releasing an options drag outside the slider and closing the popup with Escape during a drag. On both sites, scrolling regressions require the menu to retain its normal height and stay directly above its controls through document and nested-container scrolling. The menu stays inside its player and can scroll partly off-screen with it. Browser checks also cover tabs, fullscreen, short viewport height limits, Escape focus restoration, and removal with its player.

Chrome and Firefox pill interaction checks use native pointer and keyboard input on both sites. They cover grace expiry while hovered or keyboard-focused, leaving with a remaining deadline, repeated wheel adjustments, dragging outside until release, pointer focus left on the range, and Always expanded. The 220 ms animation and 1.2-second hold remain unchanged. Range unit tests separately verify release, cancellation, window blur, and disposal.

## Real-browser smoke checks

The default verification includes Chrome smoke coverage for input defaults, focus modality, rendered geometry, overflow and Twitch controls-visibility timing. To run only its UI suites:

```sh
npm run test:browser
```

The suite uses deterministic local YouTube and Twitch player contracts while routing pages onto their real origins. It checks adjustment-step layout, direct major-tick presses, keyboard ownership, options-label alignment on both tabs from 50% through 200% browser zoom, mouse and smooth wheel input, Ctrl+wheel pass-through, and platform-specific player behavior. Mode regressions verify a borderless control, visible keyboard focus through its background, and readable option text against a light native-menu backdrop. They open the native picker with mouse and keyboard, then verify that its arrow returns down after Escape, selection, or an outside click. One shared launcher selects installed Google Chrome across platforms. Set `VOLUME_SLIDER_CHROME` (or the existing `CHROME_PATH` override) to choose a specific Chrome-compatible executable. Set `VOLUME_SLIDER_SMOKE_DIST` to exercise a preserved pair of `youtube-volume-slider.user.js` and `twitch-volume-slider.user.js` artifacts, including preserved known-bad regression artifacts.

Browser launchers use isolated temporary profiles and never access the user's normal browser session. All suites share the prepared distribution files and run sequentially; the runner does not repeat builds for each browser.

Both browser suites rasterize every volume numeral from 1–100 at 75–200% scaling. They check visible-glyph centering, clearance from the arc and normalization badge, natural text proportions, and restoration after mute. These checks execute the built userscripts rather than the typography previews.

### Firefox compatibility

The default Chrome and Firefox checks each run eight synthetic Twitch audio-ownership cases. They model the source/compressor routing contract in the [official 7TV 1.10.5 package](https://addons.mozilla.org/firefox/downloads/file/5143797/7tv_new-1.10.5.xpi), without installing or executing the extension. Both source APIs are checked with normalization active, normalization still waiting for its first samples, 7TV attached before normalization is enabled, and 7TV already active before script initialization. Assertions cover early normalizer priority, audible zero, selected volume, mute, source restarts/replacement, disable/re-enable, unrelated media and the compressor button's reload explanation. Set `VOLUME_SLIDER_AUDIO_OWNERSHIP_DIST` to exercise preserved artifacts; the original Firefox build fails the parallel-source assertion, and the previous first-owner build fails the startup-priority assertion.

Firefox compatibility runs by default; use `npm run test:firefox` to isolate it. `PLAYWRIGHT_BROWSERS_PATH` can select a task-local browser cache, and `VOLUME_SLIDER_FIREFOX_RESULTS` can select the screenshots/results directory.

The Firefox suite requires continuous processed audio, peak protection, wheel/label/track synchronization, pause/mute recovery, source restarts and disable/re-enable on both sites. It also runs the 45 native gain graph cases at 44.1/48/96 kHz, including boosted stereo/surround peaks and overlapping gain changes against a continuous exponential reference. Assertions use fresh buffer channel views because Firefox detaches earlier views when a source acquires its buffer. The broader UI/zoom and synthetic page-stall suites remain Chrome-specific.

Options-button motion checks verify all three slider handles move with the menu state, return after Escape and outside dismissal, reverse during rapid toggles, preserve button geometry, and switch instantly under reduced motion on both sites.

Every smoke scenario rejects uncaught page errors before reporting success. This gate was verified by injecting an asynchronous exception into a temporary built artifact: the ordinary suite passed, while the altered artifact failed with the injected error.

YouTube popup-positioning regressions cover a hidden duplicate progress bar, no rendered progress bar, and an unrelated progress bar outside the current player. At two viewport widths, the suite opens and closes Options and checks that the popup stays inside the player, uses the rendered bar or button fallback, and receives pointer input. Native controls hold tests require waking YouTube's idle state when Options opens and after later autohide transitions, so the clock and scrubber keep updating after pointer exit.

Twitch regressions distinguish narrow channel, video, and clip players from compact browsing previews. Browser checks cross the old 720-pixel boundary at zoom levels from 100% through 200% and back, with Options open and page mutations between resizes. They verify that replacement mode keeps native controls hidden, retains the custom slider and Options button, and leaves the popup visible and interactive.

Volume-intent regressions simulate passive player writes and source reloads with normalization enabled in both On and Replace native modes. They keep the selected and saved level unchanged, verify five-point player arrow steps, and restore the selection on disable. A browser test checks native volume input after the site's setter runs. Another uses nested, cross-origin Twitch extension frames, including Twitch's own message forwarding, to verify one action per Space/volume key and no page scrolling. Text input, buttons, and keys consumed by the extension remain untouched. Unit tests reject messages from unrelated origins, sources, and unfocused frames, and ignore duplicate or delayed copies of an accepted command. All extension pages are local fixtures; these checks never load a real Twitch extension.

The browser suite also checks the static normalization icon in both themes and icon styles, at enlarged on-video sizes, and through output changes, pause, mute, unavailable capture, and disabled states. It verifies the original circular layout, inset upper-right placement with overlap limited to the outer ring, unclipped center and perimeter at ten zoom levels from 50% through 200%, unobscured selected values through 100%, and thumb clearance at zero volume. It preserves the slider's preferred volume, accessible descriptions, and existing mute interaction. Normal pause, mute, and zero volume keep the waveform visible; blocked/unavailable analysis and Off hide it. Its artwork stays unchanged through hiding and recovery. Audio feedback checks verify two separate detail lines, containment inside the status card, and no text overlap at six zoom levels from 50% through 200%. These UI checks use a controlled capture fixture; the separate normalization suite below covers real audio capture.

## Tooltips

Chrome and Firefox checks cover the Options label, site styling, keyboard and pointer access, scaling, scroll ownership, dismissal, and removal with the control. YouTube cases verify the controls-bar baseline, menu suppression, and immediate handoffs between native and custom labels, including fading native tooltips and keyboard focus.

Twitch cases verify hover timing, pop-in motion, reduced motion, controls hiding and reappearing, fullscreen placement, and cleanup after player removal. Hit-testing checks that the tooltip is painted above a native menu in a separate body layer. Audio-ownership checks also exercise the explanation on the disabled 7TV compressor.

## Audio normalization

The default check includes the full normalization coverage. `npm run test:normalization-browser` isolates the Chrome audio suites: twelve routed cases, four synthetic startup/refresh recordings with main-thread stalls, audible navigation/restart transitions, and 45 native gain-graph checks at 44.1/48/96 kHz. The startup waveform checks require FFmpeg on PATH or `VOLUME_SLIDER_FFMPEG` set to its executable. Set `VOLUME_SLIDER_NORMALIZATION_RESULTS` to an output directory outside the repository; results otherwise use the OS temporary directory. No live browser audio is recorded.

Chrome and Firefox transition tests record a synthetic tone on the audio render thread through graph disposal, immediate replacement, and restoring ordinary playback. They include ordinary output connections, inspect the first affected render quantum, and reject discontinuities or unprotected bursts. Routing unit tests cover replacement cancellation during a fade. Lifecycle fixtures advance media, timeout and animation clocks together; disable assertions wait for the bounded fade rather than requiring an abrupt synchronous cut.

The browser cases require capture to follow protected media attachment and keep one input while initial frames are withheld for 1.7 seconds. Output must remain silent through that priming without entering ordinary-volume backoff; separate unit tests retain the 1.5-second established-stream watchdog and bound missing first measurements. They also check native frames, worklet analysis, CSP-blocked worklets, unavailable input, blocked activation, stereo linking, mono input, sample ceilings, controls, selected-volume persistence, source restarts/replacement and enable/disable. A worklet message regression rejects startup-only notifications after meaningful programme measurement. The frozen packet-renderer waveform regression and earlier live results remain in the local analysis evidence, not in shipped code.

Node tests use controlled routing/analysis stubs for lifecycle contracts. Watchdog tests honor actual timer delays and check reduced player reads and deduplicated paused diagnostics. Shared-context tests cover ordinary routes, multiple players, detachment, play racing with asynchronous suspension, and pause/removal racing with asynchronous resume. Initial activation tests also pause before resume completes, then require protected playback to resume through the same source. Chrome and Firefox require a frozen render clock during pause and automatic resumption with the original source, including after normalization is disabled. Both browsers delay ordinary resume by 150 ms, pause while it is pending, require the context to return to idle, and resume again without a normalizer watchdog. Native waveform checks use real Web Audio; passing stubs are not evidence of DSP fidelity. The offline reference tests use scripts/normalization-reference.mjs, and historical reactive-controller comparisons use scripts/lib/legacy-normalization.mjs. Both are deliberately absent from the userscripts. `npm run test:normalization-compare` remains a historical comparator with optional FFmpeg/corpus inputs, not a renderer for the current native graph.

See [normalization](normalization.md) for current behavior, ownership, limits and live verification. Broader listening, Twitch ad recovery, browser suspension and end-to-end audio/video synchronization remain distinct release checks.

## Documentation screenshots

Run `npm run docs:screenshots` to build the standard scripts, check indicator geometry/zoom and refresh the PNG previews in docs/images/. The fixtures enable normalization at a selected 30% with a controlled source producing 17% output. They use no live service and show the real production settings markup, without development labels. The existing browser smoke suite remains available through `npm run test:browser`.

The release regressions also cover rapid Twitch video replacements without later DOM activity, native volume/mute read ownership after API failures and recovery, nonempty normalization descriptions, and zero settings/layout work for unrelated chat updates. Tick-alignment checks require one coalesced deferred frame while retaining immediate alignment. Firefox waveform verification repeats navigation, restart and ordinary-playback handoffs three times; any failed trial fails the suite. The unchanged waveform bound covers the first render quantum. Output-gate tests also model zero base latency with a pending renderer batch.

Chrome and Firefox run mute-feedback checks on both platforms with normalization on and off. They require M-only Muted/Unmuted labels and artwork, no custom popup from native/custom mouse clicks or Space, retained selected volume, and isolation from automatic mute changes and text input. Both platforms must show M feedback after clicking outside the player and while the page body has focus. YouTube M presses must toggle mute exactly once without reaching the native bezel handler. Native mute controls are excluded from selected-volume adoption even when nested inside a volume-control wrapper.
